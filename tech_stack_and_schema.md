# Tech Stack & Data Schema - Lingua Quest

## Objective
Provide a recommended technology stack for the MVP and a minimal Firestore schema to start backend work. Focus: fast iteration, cross-platform (iOS/Android), realtime features for Arena leaderboards, and reliable analytics.

---

## Recommended Tech Stack (MVP)

Option A — Unity game client (recommended if mini-games are animation-heavy)
- Client: Unity (C#) with Unity UI (uGUI) or Unity's UI Toolkit for in-game mini-games and map
- Cross-platform: Build to iOS & Android
- Backend: Firebase (Auth, Firestore, Storage, Cloud Functions, Remote Config)
- Analytics: Firebase Analytics + Crashlytics
- Payments: Play Store / App Store in-app purchases + Firebase Cloud Functions for validation
- CI/CD: GitHub Actions → build artifacts, upload to AppCenter or Play/App Store pipelines

Option B — React Native + lightweight Unity modules
- Client: React Native (TypeScript) for UI screens + integrate Unity as native module for heavy mini-games
- Benefit: faster UI iteration for dashboards, easier bridging to web tools
- Backend: Firebase (same as above)

Recommendation: Start with Option A (Unity) if you want fluid mini-games and a consistent game feel; choose Option B if product team values quick UI iteration and web parity.

---

## Core Services
- Authentication: Firebase Auth (email, Google, Apple)
- Database: Firestore (document-based) for user progress, vault, buildings, and leaderboards
- Storage: Firebase Storage for audio files and images
- Server Logic: Cloud Functions for scheduled SRS checks, rewards, currency transactions
- Analytics: Firebase Analytics with custom events (zone_played, word_failed, vault_reviewed, purchase_made)
- Push Notifications: Firebase Cloud Messaging (FCM)

## Minimal Firestore Schema (Collections & Documents)

1) Collection: `users` (docId = uid)
- Fields:
  - `displayName`: string
  - `email`: string
  - `avatarId`: string
  - `level`: number (player level)
  - `xp`: number
  - `gold`: number
  - `gems`: number
  - `streak`: { `count`: number, `lastDate`: timestamp }
  - `createdAt`: timestamp
  - `lastActive`: timestamp

2) Subcollection: `progress` under `users/{uid}/progress`
- docId: `zone_{zoneId}`
- Fields:
  - `completedLevels`: array of levelIds
  - `stars`: number
  - `zoneXP`: number

3) Collection: `vocabulary` (global content)
- docId: wordId
- Fields:
  - `word`: string
  - `level`: string (A1/A2/B1)
  - `pos`: string (noun/verb/adj)
  - `definition`: string
  - `example`: string
  - `ipa`: string
  - `audioUrl`: string (storage path)
  - `images`: array (optional)

4) Subcollection: `memory_vault` under `users/{uid}/memory_vault`
- docId: `wordId` (refers to `vocabulary`)
- Fields:
  - `wordRef`: reference to `vocabulary/{wordId}`
  - `status`: string ("new"|"learning"|"reviewing"|"mastered")
  - `easeFactor`: number (for SRS algorithm)
  - `intervalDays`: number
  - `nextReview`: timestamp
  - `attempts`: number
  - `lastResult`: string ("correct"|"incorrect")

5) Collection: `buildings` (global building definitions)
- docId: buildingId
- Fields:
  - `name`, `costGold`, `costGems`, `buildTimeSeconds`, `benefit`, `maxPerUser`

6) Subcollection: `user_buildings` under `users/{uid}/user_buildings`
- docId: `uniqueId`
- Fields:
  - `buildingId`, `position` (map coords), `startedAt`, `completedAt`, `isActive`

7) Collection: `leaderboards`
- docId: `weekly_{YYYY_WW}`
- Fields:
  - `topPlayers`: array of { uid, xp, rank }

8) Collection: `transactions` (for audit)
- docId: autogenerated
- Fields:
  - `uid`, `type` (earn/spend/purchase), `amount`, `currency` (gold/gems), `meta`, `createdAt`

## SRS & Scheduled Jobs
- Implement SRS scheduling as Cloud Functions (cron) to update `nextReview` dates and send push reminders.
- Use a lightweight SM2-like algorithm for intervals; store `easeFactor` and `intervalDays` per word.
- Cloud Function tasks:
  - Daily: compute review queue for each user (could create a summary doc `users/{uid}/daily_review`) and send push notification if queue > 0
  - Transactional: on purchase/spend - validate funds and write `transactions` record

---

## APIs & Security
- Use Firestore security rules to prevent cheating:
  - Validate that `xp` only increases via server functions or validated client increments.
  - Secure `transactions` writes via authenticated Cloud Functions.
- Use role-based claims for admin content creators (upload vocabulary, set zones).
